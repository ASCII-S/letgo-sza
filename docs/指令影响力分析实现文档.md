## 1. 概述

### 1.1 目标

在故障注入前**静态预分析**指令对后续的影响能力，核心关注：

1. **活性分析 (Liveness Analysis)**: 判断指令定义的值是否在后续被使用
2. **死指令检测 (Dead Definition Detection)**: 识别定义后从未被使用的指令
3. **数据流影响 (Data Flow Impact)**: 追踪 def-use 链，计算值传播范围
4. **控制流影响 (Control Flow Impact)**: 分析指令对程序执行路径的影响

### 1.2 应用场景

- **注错阶段**: 优先选择高影响力指令进行故障注入，提高崩溃检测效率
- **修复阶段**: 评估指令的修复潜力，辅助判断修复策略
- **实验分析**: 研究影响力与崩溃率、SDC率的相关性

## 2. 影响力指标体系

### 2.1 数据流指标 (Data Flow Metrics)

| 指标 | 字段名 | 类型 | 定义 | 计算方法 |
|------|--------|------|------|----------|
| 定义使用距离 | `def_use_dist` | int | 从定义到首次使用的指令数 | 追踪寄存器 def→use 链 |
| 使用次数 | `use_count` | int | 该定义被后续指令使用的次数 | 统计所有 use 点 |
| 死定义标记 | `is_dead` | bool | 定义后在重定义前是否被使用 | def 后无 use 即为死指令 |
| 活跃范围 | `live_range` | int | 从定义到最后一次使用的指令跨度 | def→last_use 距离 |

### 2.2 控制流指标 (Control Flow Metrics)

| 指标 | 字段名 | 类型 | 定义 | 计算方法 |
|------|--------|------|------|----------|
| 循环内标记 | `is_in_loop` | bool | 指令是否位于循环体内 | 检测回边 (back edge) |
| 控制流指令 | `is_control_flow` | bool | 是否为跳转/调用指令 | 检查 JMP/CALL/RET 等 |
| 内存写操作 | `is_mem_write` | bool | 是否为内存写指令 | 检查 MOV [mem], reg 等 |

### 2.3 综合影响力分数 (Influence Score)

```
InfluenceScore = f(use_count, live_range, def_use_dist, is_control_flow, is_mem_write, is_in_loop)
```

**评分算法** (参见 `instInfluence.cpp:CalculateInfluenceScore`):

```cpp
float CalculateInfluenceScore(const InstInfluence& info) {
    // 死指令得分为 0
    if (info.is_dead_def) return 0.0f;

    float score = 0.0f;

    // 1. 使用次数权重 (max 10分)
    score += min(info.use_count * 2.0f, 10.0f);

    // 2. 活跃范围权重 (max 5分)
    score += min(info.live_range / 10.0f, 5.0f);

    // 3. 定义-使用距离 (max 3分)
    if (info.def_use_distance > 0 && info.def_use_distance < 10) {
        score += 3.0f;
    } else if (info.def_use_distance < 50) {
        score += 1.5f;
    }

    // 4. 控制流指令加成 (bonus 5分)
    if (info.is_control_flow) score += 5.0f;

    // 5. 内存写操作加成 (bonus 3分)
    if (info.is_memory_write) score += 3.0f;

    // 6. 循环内指令加成 (乘以 2)
    if (info.is_in_loop) score *= 2.0f;

    return min(score, 30.0f);  // 最高 30 分
}
```

## 4. 核心模块详解

### 4.1 Pin 工具: instInfluence.cpp

**文件位置**: `mypinfii/instInfluence.cpp`

**功能**: 动态分析程序执行，收集每条指令的数据流和控制流信息

**核心数据结构**:

```cpp
// 寄存器定义信息
struct DefInfo {
    ADDRINT def_pc;           // 定义点 PC
    UINT64 def_seq;           // 定义时的指令序号
    int use_count;            // 使用次数
    ADDRINT first_use_pc;     // 首次使用的 PC
    ADDRINT last_use_pc;      // 最后使用的 PC
    bool is_dead;             // 是否死定义
};

// 指令影响力信息
struct InstInfluence {
    ADDRINT pc;
    string mnemonic;
    // 数据流指标
    int def_use_distance;
    int use_count;
    bool is_dead_def;
    int live_range;
    // 控制流指标
    bool is_in_loop;
    bool is_control_flow;
    bool is_memory_write;
    // 综合分数
    float influence_score;
};
```

**KNOB 参数**:

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `-o` | influence_catalog.csv | 输出文件路径 |
| `-pc_start` | 0 | 分析起始 PC |
| `-pc_end` | 0xFFFFFFFF | 分析结束 PC |
| `-window` | 500 | 分析窗口大小 |
| `-only_memory` | 0 | 仅分析内存操作 |

**输出格式** (CSV):

```csv
pc,mnemonic,regmm,reg,def_use_dist,use_count,is_dead,live_range,is_in_loop,is_control_flow,is_mem_write,influence_score
4202512,mov,rsi,,3,5,0,47,1,0,0,18.50
4202520,add,rax,,0,0,1,0,0,0,0,0.00
```

**编译方法**:


```python
from scipy import stats

df = pd.read_csv('analysis.csv')
```

## 7. 技术细节

### 7.1 Def-Use 链追踪算法

```
对于每条指令 I:
    1. 分析读寄存器 (use)
       - 查找该寄存器的当前定义点
       - 更新定义点的 use_count++
       - 标记定义点 is_dead = false
       - 更新 def_use_distance (首次 use)
       - 更新 live_range (每次 use)

    2. 分析写寄存器 (def)
       - 检查该寄存器的旧定义
         - 如果 use_count == 0, 标记旧定义为死指令
       - 记录新定义点
       - 初始化 is_dead = true
```

### 7.2 循环检测算法

```
检测回边 (Back Edge):
    如果 控制流指令 跳转到 更小地址:
        标记为循环
        标记 [target, current_pc] 范围内的指令为 is_in_loop
```

### 7.3 日志解析正则表达式

```python
# analyze.py 中使用的正则表达式
re.search(r'DefUseDist:\s*(\d+)', feature_text)
re.search(r'UseCount:\s*(\d+)', feature_text)
```

## 8. 已知限制

1. **静态 PC 范围**: 需要预先指定分析的 PC 范围 (`pcstart`, `pcend`)
2. **动态运行依赖**: 需要运行一次程序才能获取动态数据流信息
3. **循环检测简化**: 仅通过回边检测，可能遗漏复杂的循环结构
4. **跨函数分析**: 当前实现不追踪函数调用边界的数据流
