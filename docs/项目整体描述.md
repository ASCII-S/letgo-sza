# LetGo 故障注入与容错框架 - 项目整体描述

## 项目概述

LetGo 是一个基于 Intel Pin 动态二进制插桩工具的故障注入与容错研究框架。该框架用于研究程序在硬件故障（如单比特翻转）影响下的行为，以及自动恢复机制的有效性。

## 项目架构

### 核心组件

```
letgo/
├── configure.py          # 全局配置文件
├── letgo_wrapper.py      # 主运行包装器
├── faultinject.py        # 故障注入逻辑
├── sighandler.py         # 信号处理与恢复框架
├── InstPoolMaker.py      # 指令池生成器
├── analyze.py            # 结果分析工具
├── sdcjudger.py         # SDC（静默数据损坏）判定
├── findins.py           # 指令查找工具
└── gen_asm.py           # 汇编代码生成
```

## 执行流程

根据 Readme.md 的描述，完整的实验流程如下：

### 1. 配置阶段（configure.py）

**功能描述：** 集中管理所有实验参数和路径配置

**主要配置内容：**
- **程序配置：**
  - `progname`: 待测程序名称（从支持的 benchmark 列表中选择）
  - `progbin`: 程序二进制路径
  - `optionlist`: 程序运行参数

- **注错类型配置：**
  - `inject_random_or_targeted`: 注错模式（"random" 或 "targeted"）
  - `select_type`: 目标指令类型（mov、integer、float、call_ret、cmp、div等）
  - `only_memory`: 是否只注错内存相关指令
  - `high_bit_fault`: 是否在寄存器高位注错

- **实验参数：**
  - `numFI`: 实验次数
  - `num_start_from` / `num_end_at`: 日志起止索引
  - `pcstart` / `pcend`: 注错地址范围
  - `minCountInstInj`: 对同一 PC 重复注错的最小次数

- **路径配置：**
  - 结果文件夹：`BenchmarkResult` 或 `TargetedBenchmarkResult`
  - 分析文件夹：`analysis` 或 `TargetedAnalysis`
  - 黄金输出路径：`golden_output`

- **支持的 Benchmark：**
  - Rodinia: amg, backprop, bfs, hotspot, kmeans, nn 等
  - Mantevo: HPCCG, miniFE, miniMD, miniAMR
  - NPB-SER: bt, cg, ep, ft, is, lu, mg, sp, ua
  - PolyBench: 2mm, bicg, correlation, fdtd-2d 等

### 2. 运行阶段

#### 2.1 主控程序（letgo_wrapper.py）

**功能描述：** 协调整个故障注入实验流程

**核心流程：**
1. **获取指令总数：**
   - 使用 Pin 的 instcount 工具统计程序总指令数
   - 写入 `pin.instcount.txt`

2. **生成注错位置池（针对 targeted 模式）：**
   - `generate_mnemonic_count_file()`: 生成指令助记符统计
   - `generate_catalog()`: 根据指定指令类型生成目录
   - `generate_Pool_from_catalog()`: 从目录中生成注错位置池

3. **执行注错实验循环：**
   ```python
   for i in range(start, end):
       sig = sighandler.SigHandler(totalcount, i)
       sig.executeProgram(sig.process)
   ```

4. **日志管理：**
   - 检测 log 文件夹，自动计算起始索引
   - 每次实验生成独立的 log 文件

**关键函数：**
- `execute(execlist, out, err)`: 执行外部命令并设置超时
- `silentremove(filename)`: 安全删除文件
- `find_max_log_suffix(directory)`: 查找最大日志序号

#### 2.2 故障注入模块（faultinject.py）

**功能描述：** 实现两种故障注入方法

**核心类：** `FaultInjector`

**主要功能：**

1. **随机位置查找（getBreakpoint）：**
   - 并行搜索有效的注错位置
   - 验证 PC 地址在有效范围内
   - 确保目标寄存器有效

2. **故障生成（generateFaults）：**
   - 通过位翻转生成故障值
   - 支持 32/64 位寄存器
   - 可选高位或随机位翻转

3. **下一条指令获取（getNextPC）：**
   - 获取当前指令的下一条指令地址
   - 提取写寄存器列表
   - 分析栈操作信息

**关键数据文件：**
- `instruction`: 当前指令信息（PC、寄存器）
- `iteration`: PC 在动态执行中的迭代次数
- `nextpc`: 下一条指令地址
- `stacksize`: 栈帧大小

#### 2.3 信号处理与恢复框架（sighandler.py）

**功能描述：** 实现 LetGo 容错框架的核心恢复逻辑

**核心类：** `SigHandler`

**主要功能：**

1. **GDB 交互管理：**
   - `gdb_send()`: 统一的 GDB 命令发送接口
   - `gdb_send_extended()`: 支持自定义 expect 模式
   - 可控的详细输出模式（`verbose_gdb`）

2. **故障注入方式：**

   **方式一：基于断点（inject_inst_by_breakpoint）**
   - 在目标 PC 设置断点
   - 到达断点后单步执行并修改寄存器值
   - 适用于 targeted 模式

   **方式二：基于 Pin 工具（inject_inst_by_faultinjection）**
   - 使用 Pin 的 faultinjection.so 注入故障
   - 通过远程调试端口连接
   - 适用于 random 模式

3. **LetGo 恢复框架（letgo_frame）：**

   **核心修复策略：**

   - **h_1（栈读取修复）：**
     - 针对栈读取指令（flag=2）
     - 重新计算内存地址：`address = base + displacement + index * scale`
     - 从计算出的地址读取正确值并恢复到目标寄存器

   - **h_2（非栈操作修复）：**
     - 针对非栈读取指令
     - 将目标寄存器设置为默认值 0
     - 假设内存中零值较多

   - **h_3（栈指针修复）：**
     - 检测栈溢出：`|rsp - rbp| > stack_frame_size`
     - 根据栈帧大小修复 rbp 或 rsp
     - 设置 PC 为当前指令（重新执行）

4. **错误传播检测（error_spread）：**
   - 单步执行最多 50 条指令
   - 记录从注错点到崩溃点的传播距离
   - 输出传播长度（如 "Valid Inj2Sig: 25"）

5. **崩溃后处理（handle_after_injection）：**
   - 监测程序是否接收到信号
   - 如接收信号，启动 LetGo 修复并检测二次崩溃
   - 如未接收信号，可能为 SDC（静默数据损坏）

**实验结果分类：**
- **Masked**: 故障被屏蔽，程序正常完成
- **SDC**: 程序完成但输出错误
- **C-Masked**: 崩溃后修复成功，输出正确
- **C-SDC**: 崩溃后修复成功但输出错误
- **Recrash**: 修复后再次崩溃

#### 2.4 指令池生成器（InstPoolMaker.py）

**功能描述：** 为 targeted 模式生成注错位置池

**主要功能：**

1. **生成指令统计（generate_mnemonic_count_file）：**
   - 使用 `distributionInstCata.so` 统计各指令助记符出现次数

2. **生成指令目录（generate_catalog）：**
   - 使用 `saveInstcategory.so` 根据指定类型提取指令
   - 生成包含 PC、寄存器、迭代次数的 CSV 文件

3. **从目录生成池（generate_Pool_from_catalog）：**
   - 从目录中选择前 80 条指令
   - 为每条指令生成多个注错机会（默认 20 次）
   - 保证 PC 的重复注错次数

4. **从池中读取（readArgsFromPool）：**
   - 从池尾部取出注错参数
   - 用完即删，确保不重复

### 3. 分析阶段（analyze.py）

**功能描述：** 解析日志文件，生成 CSV 数据和可视化图表

**核心流程：**

1. **日志解析（read_logs）：**
   - 遍历 log 文件夹
   - 统计崩溃次数（flag: 0=masked, 1=一次崩溃, 2=二次崩溃）
   - 调用 `extract_values_and_append_to_csv` 提取详细信息

2. **信息提取（extract_values_and_append_to_csv）：**

   **提取的关键信息：**
   - **注入参数：** regmm, reg, pc, iteration, dynamicInstNum
   - **注入指令：** ins, opcode, Func（函数名）
   - **崩溃信息：** Sig1pc, Sig1Ins, Sig1Ope, Sig1Func
   - **修复策略：** Heuristic (h_1, h_2, h_3)
   - **错误传播：** ErrSpd_Inj, ErrSpd_Fix
   - **SDC 判定：** bias, tolerance

   **解析的关键字符串标记：**
   - `"-randinst"`: 提取动态指令序号
   - `"args ready for set breakpoint"`: 提取注入参数
   - `"display the inject inst start"`: 提取注入指令
   - `"Program received signal"`: 提取崩溃信号
   - `"Letgo in!"`: 标记 LetGo 启动
   - `"h_1"` / `"h_2"` / `"h_3"`: 标记修复策略
   - `"Valid Inj2Sig"` / `"Valid Fix2Sig"`: 错误传播长度

3. **指令信息补全（findins.py）：**
   - 使用 `findinsbyasm()` 根据 PC 从汇编文件中查找指令
   - 补全 CSV 中缺失的 Ins、Ope、Func 字段

4. **生成可视化图表：**

   **图表类型：**
   - **pic1**: 崩溃率对比（修复前后）
   - **pic2**: 动态执行进程与崩溃率关系
   - **pic3**: 崩溃后继续执行的成功率
   - **pic4**: 崩溃类型分布（C-Masked, C-SDC, Recrash）

   **表格类型：**
   - **Tab1**: 按函数统计的可修复性
   - **Tab2**: 按信号类型统计
   - **Tab3**: 按注入寄存器统计
   - **Tab_result**: 总体结果统计

### 4. SDC 判定阶段（sdcjudger.py）

**功能描述：** 判定程序输出是否为静默数据损坏（SDC）

**核心功能：**

1. **添加 SDC 判定结果到日志（Add_SDC_result_to_alllog_common）：**
   - 遍历所有 log 文件
   - 比较程序输出与黄金输出
   - 将比较结果追加到 log 文件

2. **不同程序的比较策略：**

   - **强比较（strong_compare_outputs）：**
     - 用于 bfs, backprop, nn, kmeans 等
     - 要求输出完全一致

   - **容差比较（hotspot_compare_outputs）：**
     - 用于 hotspot 等数值计算程序
     - 允许在 tolerance 范围内的误差

   - **特定行比较（miniMD_compare_outputs）：**
     - 只比较特定标记后的数据行
     - 忽略时间等不相关列

   - **残差比较（miniFE_compare_outputs, HPCCG_compare_outputs）：**
     - 提取 "Final Resid Norm" 或 "Final residual"
     - 比较残差是否在容差范围内

   - **相对误差比较（polybench_compare_outputs）：**
     - 用于 PolyBench 测试集
     - 计算最大相对误差
     - 支持配置相对误差容差

3. **输出移动（SDC_saver）：**
   - 将程序输出移动到 `sdcout` 文件夹
   - 以 `log_{index}_{output_name}` 格式命名

### 5. 辅助工具

#### 5.1 汇编生成（gen_asm.py）

**功能：** 使用 objdump 反汇编二进制文件

```python
def disassemble_binary():
    objdump -d {binary} > {asm_file}
```

#### 5.2 指令查找（findins.py）

**功能：**
- `decpc_to_op(decpc)`: 根据十进制 PC 查找操作码
- `extract_instruction_from_asm()`: 从汇编文件批量提取指令信息
- `judge_address_in_asm()`: 判断地址是否在汇编文件中

#### 5.3 其他脚本

- `countlog.py`: 统计 log 数量
- `del_log.py`: 批量删除 log
- `gatherCsv.py`: 收集 CSV 文件

## 关键技术点

### 1. Intel Pin 动态插桩

**使用的 Pin 工具：**
- `instcount.so`: 统计指令总数
- `randomInst.so`: 随机选择指令
- `determineInst.so`: 确定指令迭代次数
- `findnextinst.so`: 查找下一条指令
- `faultinjection.so`: 执行故障注入
- `saveInstcategory.so`: 保存指令类别
- `distributionInstCata.so`: 分析指令分布

### 2. GDB 自动化

**使用 pexpect 实现：**
- 自动化 GDB 命令执行
- 信号捕获和处理
- 寄存器和内存操作
- 程序流程控制

### 3. 容错策略

**LetGo 三大启发式修复策略：**
1. **h_1**: 基于栈信息的精确修复（地址计算）
2. **h_2**: 基于统计的默认值修复（零值假设）
3. **h_3**: 基于栈帧的指针修复（检测栈溢出）

### 4. 结果分类

**五类实验结果：**
- **Masked**: 完全屏蔽（无崩溃，输出正确）
- **SDC**: 静默数据损坏（无崩溃，输出错误）
- **C-Masked**: 崩溃后修复成功（崩溃→修复→输出正确）
- **C-SDC**: 崩溃后修复但输出错误（崩溃→修复→输出错误）
- **Recrash**: 修复失败（崩溃→修复→再次崩溃）

## 使用示例

### 1. 随机注错实验

```bash
# 1. 配置 configure.py
waittochangebyscrips = "backprop"
inject_random_or_targeted = "random"
numFI = 5000

# 2. 进入工作目录
cd letgo_pinfi/letgo_pinfi1

# 3. 运行实验
bash runletgo.sh

# 4. 分析结果
cd ../../
python analyze.py

# 5. 查看结果
# CSV: ./analysis/CSV/backprop.csv
# 图表: ./analysis/PIC/
```

### 2. 目标指令注错实验

```bash
# 1. 配置 configure.py
waittochangebyscrips = "correlation"
inject_random_or_targeted = "targeted"
select_type = "div"
numFI = 5000

# 2. 进入工作目录
cd letgo_targeted/letgo_targeted1

# 3. 运行实验
bash runletgo.sh

cd ../../
python analyze.py

# 5. 查看结果
# CSV: ./TargetedAnalysis/correlation/CSV/correlation_div.csv

```

### 3. 生成特定图表

```bash
# 生成所有图表
python analyze.py -p all

# 生成特定图表
python analyze.py -p 1  # 崩溃率对比图
python analyze.py -p 2  # 动态执行-崩溃率图

# 生成所有表格
python analyze.py -t all

# 生成特定表格
python analyze.py -t Sig1Func  # 按函数分组
python analyze.py -t injreg    # 按注入寄存器分组
```

## 注意事项

1. **实验隔离：**
   - 每组参数使用独立文件夹
   - 避免静态分析文件冲突

2. **文件清理：**
   - 定期清理中间文件（instruction, iteration, nextpc）
   - 存档旧实验结果

3. **参数一致性：**
   - 分析时确保 configure.py 参数与实验时一致
   - 或使用命令行参数显式指定

4. **硬盘管理：**
   - 实验结果可能占用大量空间
   - 定期移动到外部存储（./mnt/）

5. **并发执行：**
   - 使用 tmux 管理多个实验
   - 确保不同实验使用不同文件夹

## 扩展支持

### 添加新 Benchmark

1. 在 `configure.py` 中添加程序配置：
   ```python
   elif progname == "new_prog":
       progbin = "/path/to/binary"
       optionlist = ['args']
       pcstart = "start_addr"
       pcend = "end_addr"
   ```

2. 配置输出文件名：
   ```python
   if progname == 'new_prog':
       output_name = 'output.txt'
   ```

3. 配置黄金输出路径：
   ```python
   if progname == 'new_prog':
       golden_output = "/path/to/golden/output.txt"
   ```

4. 添加 SDC 比较函数（如需特殊处理）：
   ```python
   def new_prog_compare_outputs(this_output, golden_output, tolerance):
       # 实现比较逻辑
       pass
   ```

### 添加新的修复策略

在 `sighandler.py` 的 `letgo_frame()` 中添加新的条件判断和修复逻辑。

## 总结

LetGo 是一个完整的故障注入与容错研究框架，具有以下特点：

1. **自动化程度高：** 从故障注入到结果分析全流程自动化
2. **灵活性强：** 支持多种注错模式和修复策略
3. **可扩展性好：** 易于添加新的 benchmark 和修复策略
4. **结果详尽：** 生成详细的日志、CSV 和可视化图表
5. **实用性强：** 适用于容错机制研究和程序可靠性评估

该框架为研究程序容错能力提供了强大的工具支持，可以系统地评估不同修复策略的有效性，并深入分析故障传播和程序行为。
